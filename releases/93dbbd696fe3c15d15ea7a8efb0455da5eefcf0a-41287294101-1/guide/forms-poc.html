▦ sheet-db · Public Forms proof

Set up once. Close the Sheet.

This proof keeps real rows in one worksheet per table. Requests arrive through a Google Form, and the app reads the script’s confirmations from the public spreadsheet. The background script runs while the Sheet is closed.

Use a disposable test database. Read access is public and writes have no secret or authorization in this proof. Anyone with the Form details can submit database commands. Use made-up data.

1. Install the template source once

This is the maintainer’s first installation in desktop Google Sheets. There is no hosted template link yet. Once you prepare a clean template, other users can copy it and skip this file-installation stage.

  1. Create a blank Google Sheet and give it a test name.
  2. Choose Extensions → Apps Script.
  3. Download the files below. Replace Code.gs with the supplied Code source. Add a script file named Forms and paste the Forms.gs source into it.
  4. Add an HTML file named Panel and paste Panel.html into it. This preserves the earlier connector’s sidebar compatibility; the Forms proof uses its own setup dialog.
  5. In the script editor’s Project Settings, enable Show “appsscript.json” manifest file in editor. Open that file and replace its contents with the supplied manifest.
  6. Save all files and reload the spreadsheet. Its menu should now include sheet-db.

All files as text (.zip)Code.gsForms.gsPanel.htmlManifest

The ZIP contains text files for copying. Use the original Apps Script filenames above. JavaScript files should contain JavaScript, Panel should contain HTML, and the manifest should contain JSON.

2. Run the database setup

  1. In the spreadsheet, choose sheet-db → Set up public Forms POC.
  2. Approve Google’s requested permissions for your own script. If Google returns you to the Sheet before setup finishes, choose the setup action again.
  3. Read and accept the prompt to make this test spreadsheet publicly viewable. Setup creates and publishes your Form, links its response destination, installs the background trigger and prepares the records and confirmation tabs.
  4. Copy the complete connection JSON shown in the setup dialog.
  5. Open the proof app, paste that JSON into Connection JSON from your Sheet, and choose Connect database.

The app sends a read request and waits for its public confirmation before showing Connected through Forms. Connection details are saved on this device when browser storage is available. You can then close the spreadsheet.

The background script still validates tables and revisions. For this proof, even reads use a Form command so manual Sheet edits are checked before results are returned. This adds round-trip delay compared with reading raw worksheet cells.

3. Verify the complete flow

Run these checks yourself in the browser you intend to use. A local automated check cannot prove Google’s live permissions, Form delivery or mobile browser behavior.

  1. Connect using the generated JSON. Close the spreadsheet and script editor tabs.
  2. Choose Run connection check. All seven steps should pass: create, read, update, retry without duplication, reject an outdated edit, delete, and confirm deletion. Keep the app open while it works.
  3. Reload or close and reopen the app. It should reconnect using the saved details, without opening a Sheet panel. Run the check again.
  4. On your phone, open the app and paste the same connection JSON once. With the spreadsheet closed, connect and run the complete check. Reopen the app and confirm that reconnection also works there.
  5. Open the spreadsheet’s records tab. Headings are in row 1, types in row 2, and data begins on row 3. Enter a made-up label in an empty row, leaving managed columns blank. Finish typing, close the Sheet and choose Process Sheet edits & refresh in the app. The new record should appear with an ID and revision.
  6. Change that label directly in the Sheet, finish editing, and refresh in the app. The changed value should appear with an advanced revision. Finally, delete its entire row in the Sheet and refresh to confirm it disappears.
  7. Choose Forget connection. Reload and confirm the app asks for connection JSON again.

If a write times out, keep the page open and use Retry interrupted check when offered. A timeout means the outcome is unknown; the original operation ID prevents a retry from creating a duplicate.

Record the phone/browser, Google account type, elapsed time, and any failed step. Passing the local tests alone is not a live Google or mobile verification.

4. Prepare a reusable template

Keep a clean master Sheet with the four source files installed and no user data. Ideally, make this master before running database setup. Share the master as a viewable template and use its Google Sheets copy link for onboarding.

A new user’s target flow is copy template → run setup and approve permissions → paste connection JSON. They receive the script with the Sheet copy. Setup must create that copy’s own Form, trigger and connection details, rather than reuse the master’s resources.

Validate the copy flow with a second Google account before distributing the template link. Google permission approval remains a user action. The repository supplies the source and setup automation; creating and verifying the actual Google-owned master template is a separate live step.

Form submissions retain command payloads, and public confirmation rows may retain result snapshots until cleanup. Deleting a live table row does not purge those copies. This proof has no secret, no audit-history erasure feature and no production security claim.
